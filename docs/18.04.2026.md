## Andrey's Framing

- LEGO principle: hybrid architecture using tools/repos from different upstream projects.
- Verdaca is NOT another framework — it is an integration product.
- Transparent with clients about which parts come from which upstream and why.
- Promote upstream repos and their maintainer teams (they improve daily).
- Each upstream component behind a stable seam: bumping upstream = feature branch, not rewrite.
- Replaceable if upstream stops being maintained.
- Do not duplicate upstream work while they're still active.
- Own: brand, know-how, marketing, final product. Suppliers: 3rd-party open-source tools (MIT-licensed).
- Mental model: auto manufacturer — brand/IP/assembly is mine; suppliers provide engine parts.

## Round 1 — Key Positions

### 🏗️ Winston (Architect)

**Reframe:** "LEGO" is misleading — bricks interlock because they share one stud standard. The six upstreams (TONL, Pi-Mono, Mem0, Beads, Forge, RTK) have six *different* kinds of contract. Correct internal metaphor: **Unix pipes with typed sockets.** Keep "LEGO" for the client deck.

**Seam shape — one pattern, applied six times:**
- **Port** = pure Python Protocol + Pydantic DTOs + explicit error taxonomy. No upstream imports. Lives forever. Location: `src/verdaca/ports/`.
- **Adapter** = thin translator that imports the vendored upstream. Expected to be rewritten on every upstream bump. Location: `src/verdaca/adapters/<upstream>/`.
- **Vendored submodule** = `vendor/<upstream>/` as a git submodule pinned to a specific commit. Read-only. No in-tree patches; upstream PR + bump submodule pointer instead.
- **Contract tests** = one shared pytest suite per port at `tests/ports/test_<port>_contract.py`. Enforces the stud-and-hole.

**Verdaca-owned (never delegate upstream):**
1. Ports layer (the six Protocol definitions — Verdaca's spine)
2. Orchestration/pipeline kernel (Stage 4–6 work)
3. Contract test suites (one per port, version-independent)
4. MAC + test-strategy enforcement (16-entry no_waiver allow-list, 215 MAC-T catalog)
5. FastAPI/Next shell (stays thin, talks only to ports)
6. OTEL observability wiring (ratified Stage 5.5; Verdaca normalizes upstream signals)

**Rebuild moves (5–6 weeks total):**
1. Extract ports from current call sites (~1.5 wk) — grep direct upstream imports, pull signatures to `src/verdaca/ports/`
2. Reorganize repo into ports/adapters/vendor layout (~1 wk) — one atomic PR
3. Write six contract test suites (~2 wk) — the move that makes "replaceable" falsifiable
4. Build upstream-bump workflow (~0.5 wk) — monthly auto-PR with contract-test gate
5. Write `UPSTREAM.md` transparency manifest (~0.5 wk) — page sent to every POV prospect

**Disagreement:** "Hot-swappable if upstream dies" is expensive to *guarantee* (requires a second reference adapter per port). Softer honest claim: **replaceable with 2–4 weeks of adapter work, proven by contract suite.**

### 🧼 Cleo (Clean Code Reviewer)

Six upstreams, five languages, five release cadences = supply-chain attack surface.

**CRITICAL rules:**
- **C-1: Hash-pinned vendoring** — commit SHA + sha256 in per-language lockfiles. CI job `supply-chain-verify` rejects any lockfile diff without matching SBOM entry. No `main`, no `latest`, no `^1.2`.
- **C-2: Adapter contract tests at every seam, upstream-version-parameterized** — `contracts/<name>_contract_test.py` against N supported upstream versions in a CI matrix. PR-gate fails if suite drops below ratified floor.
- **C-3: SBOM generated and diffed on every build** — CycloneDX/SPDX at `/sbom/verdaca-<sha>.json`. CI fails on new transitive dependency without license classification + CVE scan.

**WARNING rules:**
- **W-1: CVE monitoring wired to lockfile** — Dependabot + osv-scanner + cargo-audit + pip-audit + govulncheck + npm audit nightly; 72-hour SLA on HIGH+.
- **W-2: License audit gate** — `/vendored/<name>/LICENSE-INVENTORY.md`; allow-listed SPDX only; GPL/AGPL/SSPL flagged explicitly.
- **W-3: Abandonment detector** — monthly scan of last-commit date, open CVEs, maintainer response latency. Auto-file Stage-7-debt ticket on threshold breach.
- **W-4: Upstream-compat test matrix in CI** — green square per (seam × supported-version) before tagging a Verdaca release.

**Highest-leverage first move:** **C-2 (adapter contract tests, version-parameterized).** Without it everything else is bookkeeping.

### 🧪 Quinn (QA Engineer) — Test Tier Plan

**Tier 1 — Port Contract Tests** (PR gate, <30s): pins method signatures, return shapes, error taxonomy, idempotency. Golden fixture per port.

**Tier 2 — Adapter Conformance Suite** (PR gate, <2min): parametrized over `[current, current-1, next-candidate]` upstream versions. Nightly matrix expands to all supported versions, emits `SUPPORTED_VERSIONS.md`.

**Tier 3 — E2E Smoke** (PR gate on bump PRs, ~5min): 8–12 happy-path tests — box boots, full deliberation completes. Not reasoning correctness.

**Tier 4 — Drift & Abandonment Monitor** (weekly cron): upstream commit recency, CVE, semver delta. Alerts at 90/180 days silence. Dashboard, not blocker.

**Do NOT test:** Mem0 vector math, TONL parser internals, Beads sled storage, Forge compaction heuristics. Upstream's CI owns those. Duplicating = inheriting their maintenance burden = defeats the seam.

**Write order before rewrite:** contracts → conformance → smoke. Drift monitor post-rewrite.
