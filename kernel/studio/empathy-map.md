### §C.x — Cross-Segment Convergence and Divergence Summary

**Where the three columns converge:**

1. **Pain stage — the binary framing is always wrong.** All three segments recognize that the "should we X or Y" question shape is incomplete; founders feel this as private doubt about the framing, COOs feel it as mild impatience with the question's structure, consultancies actively slow it down as a methodology. The binary framing is the Studio entry point across all three segments.

2. **Eval stage — all three segments want the same four output features.** Structured trade-offs, explicit dissent, named scenarios (with conditions), and explicit scope-limits (what wasn't analyzed). This is the cross-segment convergence that anchors any Studio output format ADR at 6.0.3 — the four output features are non-negotiable for any of the three hypothesized segments.

3. **Defense stage — the output has to look like a strategy deliverable, not a chatbot response.** Founders need something they can put in a board pre-read; COOs need something the exec team will trust; consultancies need something that survives white-labeling into firm voice. The shape-match criterion is cross-segment.

**Where the three columns diverge:**

1. **Decision-shape preference.** Founders want a position they can hold (conditional but committed); COOs want a framework that the team can execute against; consultancies want a firm-voice deliverable that shows density. These are three different output preferences that Studio's 6.1 architecture must serve simultaneously — the same underlying analysis, three different rendering contracts.

2. **Routing of output.** Founders route upward (board); COOs route laterally-and-upward (CEO, exec team, own team); consultancies route outward (client). The same Studio output document gets read by different audiences with different expectations — downstream format work at 6.0.3 + 6.1 must address this.

3. **Tool-provenance preference.** Founders probably don't care whether the analysis came from a tool (they care whether it's correct); COOs likely care about traceability (the analysis should be inspectable); consultancies specifically need the tool's provenance to stay invisible to the client (the firm's brand is the anchor). These three stances pull in different directions for any Studio "powered by" branding decision — a 6.0.3 ADR candidate.

**Register note (cross-cutting):** across all three segments, the muted operator-realism register holds. None of the three segments is asking for enthusiasm, urgency, or performance from a strategic-analysis tool — they're asking for substance that survives their private scrutiny. `[anchored on Mary §A.1 register note + §A.2 register note + §C.3 category conventions]`
