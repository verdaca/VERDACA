## 0. EXECUTIVE SUMMARY

The Compression Layer is Praxis's first measurable pre-sales asset: every byte and every token saved is captured as a tag on a Pi-Mono `CostRecord` and aggregated via the existing filter surface. The layer composes four components whose savings profiles and cost profiles are fundamentally different from each other, and the design must not paper over those differences — because papering over them is exactly how the "~65-75% compound savings" claim stops being honest.

**The four components, grouped by savings economics:**

| Component | Savings type | Cost to compress | Pay-it-forward? |
|-----------|--------------|------------------|-----------------|
| **TONL** | Input payload (JSON → TONL) | ~zero (pure Python encode) | No — reduces current request |
| **Forge** | Context (conversation compaction) | **zero** (deterministic, no LLM) | Yes — reduces future requests in same session |
| **Caveman** | Output prose post-generation | **non-zero** (Claude API call, Haiku-routed) | Yes — reduces downstream reads of the output |
| **RTK** | CLI command outputs | ~zero (Rust binary, <10ms) | Yes — reduces next LLM read of tool output |

The second column is the finding that most shapes this design. The hybrid-architecture doc and the Stage 2 prompt both gesture at "zero-cost compression" as if it applied uniformly; the reference implementations say otherwise. Caveman's compression is Claude-driven. RTK's savings are vendored in a binary whose token accounting is heuristic. TONL is clean Python. Only Forge is structurally zero-cost.

Three load-bearing principles follow:

1. **Pi-Mono is the oracle.** Every compression operation reports `bytes_before/bytes_after/tokens_before/tokens_after` as string-encoded tags on the `LLMRequest.tags` dict. Aggregation happens via `tracker.get_cost_summary(Filter(tag_match={"compression.mode": "on"}))`. No new `CostEvent` type is added in Stage 2 — the alignment review §6 confirms tags are the agreed integration surface.
2. **Net-positive gating is mandatory for Caveman.** Because Caveman's compression itself costs tokens, Praxis enforces a trigger gate: Caveman is invoked only when the output is expected to be read by ≥ N downstream consumers (default N=3). This keeps the "compression saves you money" narrative truthful in aggregate. The gate is a configurable policy with a default; the A/B harness measures the break-even N for each intensity level.
3. **Fail-safe fallback is per-component and observable.** Every component has a circuit breaker that, on validation failure, returns the uncompressed original with a `compression.fallback` tag naming the component that fell back. A fallback is never silent. The alignment review catches drift; the telemetry catches degradation.

**The pipeline composes as follows** (full diagram in §2):

```
Request path (outbound to LLM):
  caller → TONL encode → [optional Forge compaction] → provider SDK → LLM

Response path (inbound from LLM):
  LLM → provider SDK → TONL decode → [optional Caveman, if N-reader gate passes] → caller

Tool path (orthogonal, CLI-only):
  agent runs shell cmd → RTK binary wraps → filtered output → agent reads
```

**Measurable target:** Compound savings of 65–75% on a representative workload, where "representative" is defined by the A/B benchmark harness (§6) and the first report lands within two weeks of Amelia's first implementation merge. The blog-post headline — *"three compression layers combined deliver X% total token reduction"* — is produced by the harness, not asserted by the architecture.

The remainder of this document defines the reference deltas, the component designs, the integration contracts, the quality gates, the A/B harness, and the traceability matrix to the Stage 2 requirement set and Murat's risk register.

## 1. REFERENCE ANALYSIS (PER COMPONENT)

For each upstream reference, this section enumerates what we keep, what we change, and what we explicitly do not port. The structure mirrors Stage 1's §1 so downstream readers can cross-reference.

### 1.1 TONL — `tonl-dev/tonl`

A production-tested TypeScript text-serialization library that replaces JSON for LLM payloads by inferring schemas from uniform arrays and emitting typed, column-delimited blocks. Claim: 32–45% byte reduction versus JSON plus 5–15% tokenizer-specific savings via character-alignment to provider vocab boundaries.

#### 1.1.1 What we KEEP

| # | Pattern | Where in TONL | Why we keep it |
|---|---------|---------------|----------------|
| T1 | **Schema-inferred tabular format** | `encode.ts` detects uniform-shape arrays and emits `[count]{col:type,...}:` + delimiter-separated rows | The single largest savings source; directly proportional to array uniformity |
| T2 | **Type hint annotations** | `types.ts:u32/str/obj/list` | Enables decoder shortcut parsing and schema validation |
| T3 | **Streaming encoder/decoder** | `stream/createEncodeStream`, `stream/createDecodeStream` | O(1) memory for payloads that don't fit in RAM; Praxis will eventually encode large tool outputs |
| T4 | **Error hierarchy** | `errors/TONLError → ParseError/ValidationError/TypeError/SecurityError` | Matches the "fail loudly, never silently" principle from Stage 1 |
| T5 | **Tokenizer-aware character layout** | `utils/metrics.ts` | Where the 5-15% tokenizer-specific savings come from; needs re-grounding in actual tokenizers (see C-list) |
| T6 | **TONLDocument query/modification API** | `document.ts` | Praxis downstream agents will want to slice compressed payloads without full decode; worth porting |
| T7 | **JSON round-trip contract** | `encode/decode.ts` | Lossless round-trip is a correctness invariant, not a feature — it's MANDATORY for Praxis |
| T8 | **Security limits** | `utils/security.ts` — `MAX_NESTING_DEPTH=500`, `MAX_LINE_LENGTH=100KB`, `MAX_FIELDS_PER_LINE=10K`, ReDoS timeouts, path traversal guards | Praxis runs untrusted agent output through TONL; these limits are load-bearing |

#### 1.1.2 What we CHANGE

| # | Change | Rationale |
|---|--------|-----------|
| T-C1 | **Real tokenizers, not heuristics** | TONL's `utils/metrics.ts` uses hardcoded `char/token` ratios. Praxis has actual provider SDKs in scope (Anthropic, OpenAI, Google — see Stage 1 §5) and their tokenizer libraries (`tiktoken`, `anthropic.Client.count_tokens`, `google.generative-ai` tokenizer). Use the real libraries as the primary path, keep the heuristic as fallback for offline tests. |
| T-C2 | **Python 3.12 async-native** | Node Transform streams → Python `AsyncIterator` via `async def` + `async for`. The behavioral equivalence is direct; the API shape changes. |
| T-C3 | **Pydantic v2 schema integration** | TONL has its own schema system; Praxis already depends on Pydantic v2. Map TONL types to Pydantic field types and expose one unified schema surface. |
| T-C4 | **No float fields** | TONL has `f64` / `f32` fields for serializing JS numbers. Praxis never serializes floats through TONL when cost is involved (per Stage 1 R7). Decimal strings are serialized as `str`, decoded back to `Decimal` via Pydantic validators. |
| T-C5 | **`frozen=True` Pydantic models by default** | Matches Stage 1 convention. Mutable TONL documents use a separate class (`TONLDocument`) with explicit mutation semantics. |
| T-C6 | **Adaptive optimizer: start with 3 strategies, not 10** | TONL ships 10 optimization strategies. Praxis P0 delivers three: (a) tabular for uniform arrays, (b) delta encoding for numeric time-series, (c) column reordering for query-optimized layouts. The other seven are deferred per "no speculative code" (Stage 1 CLAUDE.md rule). |
| T-C7 | **No circular reference handling** | TONL uses WeakSet to detect cycles. Praxis forbids cyclic payloads at the Pydantic model boundary — cycles fail validation, never reach the encoder. This removes one entire class of bugs. |
| T-C8 | **Tokenizer version pinning** | Provider tokenizers change. Every encoded payload carries a `tokenizer_version` metadata header; decoder rejects payloads encoded with an unknown version. See §7 (Storage & Versioning). |

#### 1.1.3 What we DO NOT PORT

- **CLI tool and interactive dashboard.** TONL's `cli.ts` + REPL are developer tooling, not a Praxis dependency.
- **Browser shims** (`src/browser-*.ts`, `src/document-browser.ts`, `stream-browserify`). Praxis is server-side Python.
- **VS Code extension.**
- **Node-specific Buffer math.** Replaced with Python `bytes` + `memoryview`.
- **Seven of the ten optimization strategies** (bit-packing, RLE, dictionary, numeric quantization, etc.). Deferred.

### 1.2 Forge — `antinomyhq/forgecode`

A production Rust agent loop whose **deterministic** conversation-compaction subsystem is the piece Praxis wants. The Explore agent's audit confirms: **zero LLM calls in the compaction path**. The entire savings come from a template-rendered Markdown summary replacing a contiguous range of old messages, with reasoning chains explicitly preserved.

**Clarification up-front:** The hybrid-architecture doc mentioned "three modes: sage / muse / forge". The Explore agent confirmed these are **user-facing interface modes (TUI, CLI, ZSH plugin)** and are **orthogonal to compaction**. Compaction has no mode switch — it runs on a single deterministic algorithm.

#### 1.2.1 What we KEEP

| # | Pattern | Where in Forge | Why we keep it |
|---|---------|----------------|----------------|
| F1 | **Deterministic compaction algorithm** | `crates/forge_app/src/compact.rs` + `crates/forge_domain/src/compact/strategy.rs` | The core of the savings; confirmed zero-LLM in the path |
| F2 | **Retention window semantics** | `CompactionStrategy::retain(retention_window: 6)` | Last N messages never compacted; matches the Praxis "live context stays" requirement |
| F3 | **Eviction window strategy** | `CompactionStrategy::evict(eviction_window: 0.2)` | Percentage-based alternative to retention window; more conservative bound wins |
| F4 | **Tool-call / tool-result pair protection** | `compact.rs` explicitly walks the range end backward if it lands on a tool_use without tool_result | Critical for conversation validity across the compaction boundary |
| F5 | **Three-threshold trigger** | `should_compact_due_to_{tokens,turns,messages}` | Token count OR turn count OR message count — any one crosses triggers |
| F6 | **Markdown template summary** | `forge-partial-summary-frame.md` via `TemplateEngine::render` | No model, just deterministic interpolation — maps cleanly to Jinja2 |
| F7 | **Transformer pipeline** | `DropRole(System)` → `DedupeRole(User)` → `TrimContextSummary` → `StripWorkingDir` | Stateless filters; the summary shape converges regardless of input order |
| F8 | **Reasoning chain last-block injection** | `compact.rs` scans compacted range in reverse, extracts the most recent `reasoning_details`, injects into the first post-boundary assistant message | The correctness rule that keeps Extended Thinking coherent across compactions |
| F9 | **Droppable marker semantics** | Messages flagged `droppable: true` are stripped post-compaction | Matches the Pi-Mono "tags as freeform metadata" pattern |

#### 1.2.2 What we CHANGE

| # | Change | Rationale |
|---|--------|-----------|
| F-C1 | **Rust → Python 3.12 asyncio** | `Arc<ContextMessage>` becomes plain Python refs; `anyhow::Result` becomes typed exceptions from a new `compression/errors.py` |
| F-C2 | **Pydantic v2 message model** | Forge's `TextMessage` → Praxis `ConversationMessage` (Pydantic, frozen). Fields map 1:1 except `thought_signature` (Forge-internal, not needed) |
| F-C3 | **Provider-message adapter layer** | Forge lives inside its own agent loop; Praxis Forge must **translate between provider-native message shapes** (Anthropic `messages.create`, OpenAI Responses, Google Gemini) and the internal canonical message model. This adapter is a net-new layer. |
| F-C4 | **Configurable trigger thresholds with Pi-Mono-aware defaults** | Forge's defaults are unset. Praxis sets sensible defaults using Stage 1's cost math: e.g., token_threshold at 70% of the provider's context window, message_threshold at 60 messages. |
| F-C5 | **Compaction events emit to Pi-Mono** | Every compaction run tags the *next* `LLMRequest` with `compression.forge.compactions=<N>` so savings are attributable in the A/B harness |
| F-C6 | **Idempotency is explicit** | Forge's compaction is implicitly idempotent because `eviction_range` returns `None` when there's nothing to compact. Praxis makes this explicit: a property test asserts `compact(compact(X)) == compact(X)` |

#### 1.2.3 What we DO NOT PORT

- **The three "sage/muse/forge" interface modes** — orthogonal to compaction.
- **ZSH plugin, TUI, CLI parsing.**
- **`crates/forge_services/src/tools/*`** — file I/O, shell exec, etc. Praxis has its own tool layer (Stage 4).
- **Provider client code.** Praxis has Stage 1 providers.
- **Template engine crate.** Use Jinja2.
- **Dead LLM-based compaction design** (old code path around lines 121795–122070). Explicitly forbidden.

### 1.3 RTK — `rtk-ai/rtk`

A Rust binary that transparently filters CLI output through a mix of TOML-declared regex rules and hand-coded Rust state machines. Shell hooks are agent-specific (Claude Code, Copilot, Cursor, Gemini CLI) — each agent's built-in PreToolUse hook calls `rtk rewrite` to transform a command, and the agent executes the rewritten form. Telemetry lives in SQLite at `~/.local/share/rtk/tracking.db`.

**RTK is the only non-Python component in Praxis Stage 2.** It stays in Rust, ships as a precompiled binary, and Praxis wraps it with a thin Python subprocess boundary.

#### 1.3.1 What we KEEP

| # | Pattern | Where in RTK | Why we keep it |
|---|---------|--------------|----------------|
| R1 | **The Rust binary itself, unmodified** | `rtk-{target-triple}` in GitHub Releases | Performance envelope (<10ms start, 5-15ms per command) is load-bearing; re-implementing in Python would lose it |
| R2 | **`rtk rewrite "<cmd>"` invocation surface** | `src/main.rs` Clap commands | Clean narrow interface: stdin cmd → stdout rewritten cmd, exit codes 0/1/2/3 for allow/no-match/deny/ask |
| R3 | **`rtk <cmd> <args>` filter pipeline** | `src/cmds/**` + `src/filters/*.toml` | Primary savings path for known commands |
| R4 | **`rtk gain --format json` telemetry** | `src/tracking/` + `gain.rs` | Exposes savings history as structured JSON; feeds Pi-Mono via Python wrapper |
| R5 | **TOML rule DSL** | `src/filters/*.toml` | 60%+ of commands are declaratively filterable; no code for new commands |
| R6 | **Flag-aware downgrade** | Detects `--verbose/-v` / `--json` / `--quiet` and adjusts compression accordingly | Preserves agent debug experience |
| R7 | **Transparent failure** | Filter error → stderr warning + original output | Matches Praxis "never silently corrupt" principle |
| R8 | **Command registry** | `src/discover/registry.rs` — 100+ entries | Stable interface, precompiled, no re-implementation cost |

#### 1.3.2 What we CHANGE (in the Python wrapper only — Rust binary is untouched)

| # | Change | Rationale |
|---|--------|-----------|
| R-C1 | **Vendored precompiled binaries per platform** | `praxis/kernel/compression/rtk/bin/{linux_x64,linux_arm64,darwin_x64,darwin_arm64,windows_x64}/rtk[.exe]` — Praxis ships binaries rather than requiring a Rust toolchain |
| R-C2 | **Python wrapper** | `praxis.kernel.compression.rtk.RTKClient` — resolves platform, invokes subprocess, parses telemetry, handles failure |
| R-C3 | **Pi-Mono savings bridge** | After RTK filters a command, the wrapper reads `rtk gain --format json` delta and tags the nearest downstream `LLMRequest` with `compression.rtk.bytes_saved=<N>` |
| R-C4 | **Agent-facing Python adapter** | Praxis agents call `await compression.rtk.run_command(cmd)` which returns `(stdout, exit_code, savings)`; they never invoke the shell hooks — Praxis owns the invocation layer |
| R-C5 | **No shell hook installation** | The agent-specific hooks (`rtk init -g --claude`) are designed for user shells; Praxis is a library, not a shell environment. We bypass them entirely and invoke `rtk` as a subprocess. |

#### 1.3.3 What we DO NOT PORT / VENDOR

- **Shell hook scripts** for Claude Code, Copilot, Cursor, Gemini CLI — Praxis invokes RTK directly, not via agent hooks.
- **Windows PowerShell integration** — defer unless a future POV requires it.
- **The CLI tracking DB** — we read the JSON output, but we store per-invocation savings in Pi-Mono tags, not RTK's SQLite.
- **Installer (`rtk init`)** — replaced by vendored binaries.

**Design gap identified by RTK Explore:** RTK has no "read stdin, filter, write stdout" mode. It's built to wrap known commands, not filter arbitrary pre-captured blobs. This means Praxis's RTK wrapper can only compress output **at the moment a known command is executed** — not retroactively on saved logs. The Caveman layer handles the retroactive prose case.

### 1.4 Caveman — `juliusbrussee/caveman`

An LLM-driven prose compressor. **This is the finding the stage-2 prompt didn't anticipate.** The `caveman-compress` Python tool compresses by calling Claude (or the `claude` CLI as fallback) with a carefully boundary-aware prompt, then validates structural preservation (headings, code blocks, URLs) via Python regex, with up to 2 targeted-repair retries before restoring the original on failure.

**What this means for Praxis:**

1. Caveman compression is **not zero-cost**. Each call spends input + output tokens on Haiku/Sonnet.
2. Net savings are only positive when the compressed output is **read more than once downstream**. A one-shot "LLM produces output → user reads → done" pattern is a net LOSS.
3. Praxis must gate Caveman on a downstream-read predicate: *only compress if the output is expected to be consumed by ≥ N subsequent agents*. Default N=3 (break-even); configurable.
4. The Caveman `intensity` level is a **cost knob**: higher intensity = more aggressive compression = larger input prompt = more tokens spent per call. We need a calibration curve.

This is the first place in Stage 2 where the architecture explicitly departs from what the stage-2 prompt assumed. The elicitation step (2.1.5) is the right place to reconcile: Andrey may decide Caveman is out of scope for Stage 2 P0, or may accept the net-positive gate, or may ask for a rule-based fallback dialect. §10.2 flags this as the top open question.

#### 1.4.1 What we KEEP

| # | Pattern | Where in Caveman | Why we keep it |
|---|---------|------------------|----------------|
| V1 | **6 intensity levels** | `skills/caveman/SKILL.md` (lite/full/ultra/wenyan-lite/wenyan-full/wenyan-ultra) | Expressive enough for the cost/quality trade-off |
| V2 | **Multi-dialect support** (caveman-English + 文言文) | Hardcoded system prompts per dialect | Dialect selection is a one-key lookup; we keep the mechanism |
| V3 | **Structural circuit breaker** | `scripts/validate.py` — heading count, code-block byte-match, URL set match, file-path set match, bullet count ratio | The only safety net; extend it, don't replace it |
| V4 | **Targeted fix retry** | Up to 2 retries with a *targeted-repair* prompt | Avoids full recompression on minor errors |
| V5 | **Hard fallback to original** | On exhausted retries, restore backup | Matches Praxis "never silently corrupt" principle |
| V6 | **Content boundary preservation** | Prompt-level instruction: "do not touch ``` blocks, inline code, URLs, commands, paths, version numbers" | Works because Claude follows instructions well; we keep this as the first layer of defense |

#### 1.4.2 What we CHANGE (the biggest deltas in Stage 2)

| # | Change | Rationale |
|---|--------|-----------|
| V-C1 | **Net-positive gate** | New mandatory predicate: `should_compress(output) = estimated_downstream_reads >= BREAK_EVEN_N`. `BREAK_EVEN_N` is derived from the A/B harness (§6). Default N=3. If predicate is false, pass through uncompressed. |
| V-C2 | **Haiku-routed compression** | Caveman's reference uses whatever Claude the user has installed. Praxis pins compression to Haiku 4.5 (cheapest agentic-grade model) to keep the compression cost floor as low as possible. |
| V-C3 | **Pi-Mono attribution with compression cost visible** | Every Caveman call writes TWO Pi-Mono records: (a) the Haiku compression call (primary cost), (b) the compressed output metadata on the downstream request (tags). The dashboard subtracts (a) from cumulative savings so the "net savings" number stays honest. |
| V-C4 | **Semantic validation extension** | Current validation is structural only. Praxis adds two semantic checks: (i) **negation preservation** — count of "not / no / never / without / except / unless" tokens must match between original and compressed (or differ by at most 1); (ii) **number preservation** — all numeric literals in original must appear in compressed. These catch the highest-risk semantic drift cases. Full semantic similarity (embedding cosine) is flagged as a follow-up (§10.3). |
| V-C5 | **Tool-call payload safe zone** | Extend the boundary detector to recognize JSON / YAML / SQL / XML fenced regions regardless of whether they're inside a markdown code fence. Never touch them. |
| V-C6 | **Stateless library API** | Caveman is a skill system + CLI. Praxis exposes only `compress_output(text, intensity, dialect) -> CompressionResult` as the library surface. No filesystem side effects, no backup files, no CLI. |
| V-C7 | **Content-type safe-list instead of file extension** | Caveman classifies files by extension. Praxis classifies *text regions* by content pattern (markdown, code-mixed, pure-prose). Only pure-prose regions are compressed. |
| V-C8 | **Wenyan dialect gating** | Wenyan (文言文) compression is only valid when the downstream consumer is known to handle classical Chinese tokenization correctly. Gated behind an explicit `accept_wenyan: bool` flag on the caller's side; default false. |

#### 1.4.3 What we DO NOT PORT

- **Claude Code skill integration** (`/caveman` slash command, skill metadata) — not a library surface.
- **The `caveman-commit` and `caveman-review` Claude Code skills** — orthogonal to compression.
- **The `claude` CLI subprocess fallback** — Praxis has the Anthropic SDK pinned in Stage 1; no CLI fallback path.
- **Backup file management** (`.original.md` sidecar) — Praxis is stateless at the compression layer.
- **The `tiktoken` optional path** — Praxis uses the provider-native tokenizer (Stage 1 §5.2).
- **Benchmark harness** (`evals/`) — replaced by the A/B harness designed in §6 of this document, which covers the whole Compression Layer not just Caveman.

### 2.2 Request path order of operations

1. **TONL encode** is the first layer. Encoding is cheap and deterministic; doing it before compaction reduces the byte count that the compactor's token estimator sees, which sharpens the threshold decision.
2. **Forge compaction** runs second. It operates on the conversation history (not the current outbound message), so its input is the accumulated history of TONL-encoded messages. Forge may read and write the conversation state but never mutates the current outbound payload in-place — the current outbound payload is always appended after compaction.
3. **Pi-Mono `track_cost`** runs AFTER the provider returns — it's the Stage 1 boundary, unchanged. What changes is the `tags` dict on the `LLMRequest` / `CostRecord`: compression adds its attribution tags before `track_cost` is called.

### 2.3 Response path order of operations

4. **TONL decode** is first on the way back. The provider returned TONL if and only if the provider supports TONL for its output format — today, none do, so response decode is typically a no-op. The decode path exists for completeness (future providers, roundtripped internal messages).
5. **Caveman compression** is second and **gated**. The gate evaluates: (a) is the output prose (not pure code)? (b) is the output long enough to amortize compression cost (>= 500 tokens by default)? (c) is the output expected to be read by ≥ `BREAK_EVEN_N` downstream consumers? If any answer is no, pass through uncompressed. If all yes, compress → structural validate → semantic validate → return or retry.
6. **Return to caller** delivers the (possibly compressed, possibly original) output.

### 2.4 Tool path order of operations

Orthogonal because it operates on shell-command outputs, which exist outside the LLM request/response cycle. An agent calls `compression.rtk.run_command(cmd)`:
- The RTK wrapper resolves the binary for the current platform.
- Subprocess invocation: `rtk <cmd> <args...>` (not `rtk rewrite` — we're not a shell hook).
- RTK filters the output according to its registry + TOML rules + state machines.
- Wrapper captures the filtered output and reads `rtk gain --format json` to get the savings delta.
- The savings delta is held until the NEXT `LLMRequest` is constructed, at which point it's attached as a tag: `compression.rtk.bytes_saved_prior=<N>`. This attribution model means RTK's savings are associated with the *request that reads them*, not the command that produced them — which is the correct pay-it-forward accounting.
- **Orphan timeout (FMEA R.8).** If no downstream `LLMRequest` arrives within 60 seconds of the RTK call, the savings are bucketed as orphan with `compression.rtk.orphan=true` on the nightly rollup. The dashboard (§8.4) shows orphan rate; **sustained > 5% over 24 hours** is an investigation trigger (Matrix 4) — it implies agent workflows are producing CLI output that no LLM ever consumes, which is a workflow-design problem rather than a compression problem. The 5% threshold is consistent with the Caveman fallback discipline (Matrix 1 → 3% / 7%) — both choose signal sensitivity over noise tolerance at Stage 2 P0.

### 2.5 Forge's orthogonal trigger

Forge compaction runs inside the request path but its trigger is **not driven by the current request**. It's driven by the session's cumulative state:

```
Forge.trigger = any([
  session.total_tokens >= token_threshold,          # default: 0.7 * context_window
  session.user_turns >= turn_threshold,             # default: 30
  session.total_messages >= message_threshold,      # default: 60
  last_message.role == 'user' and on_turn_end_enabled,
])
```

So Forge may run zero times across a request (common — most requests don't cross any threshold) or exactly once. It never runs more than once per request, because the transformers are idempotent (property F-C6) and running twice is wasted work.

### 2.6 Failure cascade

A failure in any component falls back to that component's uncompressed input. The downstream components still run. The `compression.fallback` tag records which component fell back:

- TONL decode fails → return JSON-encoded raw string, tag `fallback=tonl`, Caveman still runs on the decoded string.
- Forge compaction fails → use original history, tag `fallback=forge`, request still goes to provider.
- Caveman compression fails (validation exhausts retries) → return original output, tag `fallback=caveman`, caller still gets content.
- RTK binary missing or crashes → return raw command output, tag `fallback=rtk`, agent still sees output.

Cascade isolation is enforced by the architecture: each component's input validator rejects malformed data with a typed exception; the orchestrator catches that exception and substitutes the uncompressed path. No component receives another component's error state.

#### 3.2.3 Compaction algorithm (deterministic)

```
function compact(conversation, config):
    if not should_compact(conversation, config):
        return CompactionResult(compacted=False, ...same conversation)

    # Choose the more conservative bound
    evict_range = evict_strategy(conversation, config.eviction_window)
    retain_range = retain_strategy(conversation, config.retention_window)
    range = min(evict_range, retain_range)   # by end index — retain further if conflict

    if range is None:
        return CompactionResult(compacted=False, reason="nothing_to_compact")

    # Walk the range END backward until we're not splitting a tool_use/tool_result pair
    end = walk_back_until_pair_complete(conversation, range.end)
    range = Range(range.start, end)

    # Extract the sequence, filter droppable, dedup consecutive user
    sequence = conversation.messages[range.start..range.end]
    sequence = apply_transformers(sequence, [
        DropRole(SYSTEM),
        DedupeRole(USER),
        TrimContextSummary(),
        StripWorkingDir(),
    ])

    # Render Markdown summary via Jinja2
    summary_text = render_template("partial_summary_frame.md.j2", {
        "message_count": len(sequence),
        "first_timestamp": sequence[0].timestamp,
        "last_timestamp": sequence[-1].timestamp,
        "participant_roles": unique(m.role for m in sequence),
        "tool_calls_summarized": [m.tool_calls for m in sequence if m.tool_calls],
        "decisions_by_agent": group_decisions(sequence),
    })

    # Extract last reasoning block from the compacted range
    # Version-tag the schema so SDK drift is detectable (FMEA F.2)
    last_reasoning = last_non_empty_reasoning(sequence)
    reasoning_schema_version = detect_reasoning_schema(last_reasoning)
    if reasoning_schema_version not in KNOWN_REASONING_SCHEMAS:
        emit_alert("forge.reasoning.unknown_schema", version=reasoning_schema_version)
        last_reasoning = None   # fall back to no-reasoning mode; never silently corrupt a chain

    # Build the new conversation
    new_messages = (
        conversation.messages[:range.start]
        + [UserMessage(content=summary_text, metadata={"synthetic": True, "source": "forge.compaction"})]
        + conversation.messages[range.end + 1:]
    )

    # Inject last_reasoning into the first assistant message post-boundary (FMEA F.6)
    # IF AND ONLY IF that message has no reasoning. If it already has reasoning, the
    # downstream chain is already coherent — preserve its reasoning verbatim and drop
    # the extracted block. Never overwrite, never merge, never append.
    first_assistant_post = next((m for m in new_messages[range.start + 1:] if m.role == ASSISTANT), None)
    if first_assistant_post and last_reasoning:
        if not first_assistant_post.reasoning_details:
            first_assistant_post = first_assistant_post.model_copy(update={"reasoning_details": last_reasoning})
        # else: first_assistant_post already has reasoning — leave it alone, discard last_reasoning

    return CompactionResult(
        compacted=True,
        messages_before=len(conversation.messages),
        messages_after=len(new_messages),
        tokens_saved=count_tokens(conversation) - count_tokens(new_messages),
        reasoning_preserved=bool(last_reasoning),
        range=range,
    )
```

**Determinism guarantees:**
- `should_compact` is a pure function of `(conversation, config)`.
- `apply_transformers` is order-stable and side-effect-free.
- `render_template` uses Jinja2 with `autoescape=False` and deterministic ordering — no randomness, no wall-clock in the template context.
- `last_non_empty_reasoning` is a deterministic reverse-iterator scan.

**Property tested:** `compact(compact(X)) == compact(X)` (idempotency).
**Property tested:** `compact` never calls any LLM provider (mocks assert zero invocations).

#### 3.3.4 Subprocess invocation

```python
async def run_command(self, argv: list[str], *, timeout_s: float = 30.0) -> RTKResult:
    rtk_argv = [str(self.binary)] + argv
    proc = await asyncio.create_subprocess_exec(
        *rtk_argv,
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE,
    )
    stdout, stderr = await asyncio.wait_for(proc.communicate(), timeout=timeout_s)

    if proc.returncode is None:
        proc.kill()
        raise RTKExecutionError("timeout")

    # Savings are read from the shared tracking DB AFTER the command runs
    savings = await self._read_latest_savings()
    return RTKResult(
        stdout=stdout.decode("utf-8", errors="replace"),
        stderr=stderr.decode("utf-8", errors="replace"),
        exit_code=proc.returncode,
        bytes_before=savings.bytes_before,
        bytes_after=savings.bytes_after,
        tokens_saved_estimate=savings.tokens_saved,
    )
```

#### 3.3.5 Savings attribution

The wrapper reads `rtk gain --format json` after each run to extract the delta for the most recent command. Because RTK's tracking DB is global and single-user, and Praxis may run many parallel tool calls, the wrapper uses RTK's per-command row identifiers (by timestamp) to disambiguate. This is racy under high concurrency — see §10.4 (open question on RTK concurrency).

#### 3.3.6 Failure modes

| Mode | Trigger | Fallback |
|------|---------|----------|
| Binary missing for platform | User installed Praxis on unsupported architecture | `RTKBinaryMissingError` — Praxis disables RTK compression for the session; all other components still work |
| Subprocess timeout | RTK hangs (unlikely, <30s envelope) | Kill subprocess, raise `RTKExecutionError`, caller receives original command output via Praxis's non-RTK agent runtime fallback (Stage 4) |
| Non-zero exit from wrapped command | The command itself failed — NOT an RTK failure | Return the command's stdout and exit code as-is; this is not a compression failure |
| Telemetry DB lock / contention | Multiple concurrent calls | Best-effort: return `RTKResult` with `bytes_before=None`; savings attribution is approximate |
| Binary crash | Segfault or panic | `RTKExecutionError`; Praxis logs and disables RTK for current session |

#### 3.3.7 The stdin-filter gap

RTK does not support "read blob on stdin, compress, write to stdout." The RTK wrapper therefore can only compress command outputs at the moment the command runs — not retroactively on saved outputs. Praxis agents must invoke `RTKClient.run_command` instead of running shell commands directly if they want compression. This is a discoverability concern addressed by Stage 4 (Agent Runtime) — the runtime auto-routes shell invocations through the RTK wrapper when available.

#### 3.4.3 Net-positive gate

```python
def should_compress(
    req: CompressionRequest,
    config: GateConfig,
    calibration: CalibrationSnapshot,
) -> tuple[bool, str]:
    # 0. Calibration freshness (FMEA V.4)
    # If the A/B harness hasn't refreshed the break-even curve within max_calibration_age,
    # we refuse to compress rather than trust a stale number. Better "no savings today"
    # than "silent net-negative this month".
    if calibration.age_seconds > config.max_calibration_age_seconds:
        return False, "calibration_stale"

    # 1. Length floor — below which compression can't amortize
    if req.text_length_tokens < config.min_tokens:
        return False, "below_min_length"

    # 2. Content type — must be prose-dominant
    classification = classify_content(req.text)
    if classification != ContentType.PROSE_DOMINANT:
        return False, f"content_type={classification}"

    # 3. Downstream read estimate — must clear break-even
    expected_savings_per_read = calibration.savings_per_read(req)
    compression_cost = calibration.compression_cost(req)
    break_even_reads = math.ceil(compression_cost / expected_savings_per_read)
    if req.expected_downstream_reads < break_even_reads:
        return False, f"below_break_even (need {break_even_reads} reads, have {req.expected_downstream_reads})"

    # 4. Wenyan gate
    if req.dialect in WENYAN_DIALECTS and not req.accept_wenyan:
        return False, "wenyan_not_accepted"

    return True, "ok"
```

The `CalibrationSnapshot` is refreshed nightly by the A/B harness (§6). It holds `savings_per_read`, `compression_cost`, `refreshed_at`, and a `prediction_error_history`. Two guards make it self-correcting rather than trust-based:

**Staleness guard (FMEA V.4):** if `calibration.age_seconds > max_calibration_age_seconds` (default 7 days per §4.4), the gate auto-denies with `reason=calibration_stale`. A stale calibration is worse than no compression — the current break-even number may no longer reflect reality.

**Ground-truth feedback loop (FMEA V.5):** the caller passes `expected_downstream_reads` at compression time, but this is a prediction. The compression layer records `(request_id, expected_reads, actual_reads_observed_in_7d)` tuples in the harness database. Each nightly harness run computes `prediction_error_pct = |expected - actual| / actual` across the last 7 days; if the median error exceeds `prediction_error_median_threshold_pct` (default 30%), the harness **raises the `break_even_reads` requirement by one** to compensate, and emits `caveman.calibration.adjusted` to the dashboard. This makes the gate self-correcting: over-predicting downstream reads gets systematically penalized until the prediction stabilizes.

def validate_structural(original: str, compressed: str) -> list[StructuralError]:
    errors = []
    # H1: heading count match
    if heading_count(original) != heading_count(compressed):
        errors.append(StructuralError("heading_count_mismatch", ...))
    # H2: code block byte-exact match
    if extract_code_blocks(original) != extract_code_blocks(compressed):
        errors.append(StructuralError("code_block_corruption", ...))
    # H3: URL set match (no loss, no addition)
    if extract_urls(original) != extract_urls(compressed):
        errors.append(StructuralError("url_drift", ...))
    # H4: file-path set match
    if extract_paths(original) != extract_paths(compressed):
        errors.append(StructuralError("path_drift", ...))
    # H5: bullet count within tolerance (FMEA V.10)
    # The threshold 0.15 below is a PLACEHOLDER pending A/B harness calibration.
    # The harness will label a corpus with "true compression merges" vs "false
    # corruption merges" and set this threshold at the 95th percentile of the
    # true-merge distribution. Default held at 0.15 until the first calibration
    # completes; see §10.11.
    bb = count_bullets(original)
    cb = count_bullets(compressed)
    if bb > 0 and abs(bb - cb) / bb > config.bullet_drift_threshold:
        errors.append(StructuralError(
            "bullet_count_drift",
            ratio=abs(bb - cb) / bb,
            threshold=config.bullet_drift_threshold,
        ))
    return errors
```

#### 3.4.5 Semantic validator (NEW — Stage 2 addition)

```python
def validate_semantic(original: str, compressed: str) -> list[SemanticError]:
    errors = []

    # S1: negation token count (coarse — catches bulk negation loss)
    neg_tokens = {"not", "no", "never", "without", "except", "unless", "cannot", "shouldn't", "don't"}
    orig_neg = count_tokens_ci(original, neg_tokens)
    comp_neg = count_tokens_ci(compressed, neg_tokens)
    if abs(orig_neg - comp_neg) > 1:
        errors.append(SemanticError("negation_drift", orig=orig_neg, comp=comp_neg))

    # S2: numeric literal preservation — every number in original must appear in compressed
    orig_numbers = extract_numeric_literals(original)
    comp_numbers = extract_numeric_literals(compressed)
    missing = orig_numbers - comp_numbers
    if missing:
        errors.append(SemanticError("number_loss", missing=missing))

    # S3: polarity pair preservation (FMEA V.2 — count-based S1 is fooled by simultaneous add+drop)
    # Maintain a small conservative antonym lexicon. Compression may change absolute counts
    # but MUST NOT flip the sign of the positive-minus-negative bias for any pair.
    POLARITY_PAIRS = [
        ("safe", "unsafe"), ("recommended", "discouraged"), ("allow", "deny"),
        ("enable", "disable"), ("required", "optional"), ("valid", "invalid"),
        ("trusted", "untrusted"), ("supported", "unsupported"), ("public", "private"),
        ("include", "exclude"), ("accept", "reject"), ("approve", "reject"),
        ("possible", "impossible"), ("correct", "incorrect"), ("expected", "unexpected"),
    ]
    for positive, negative in POLARITY_PAIRS:
        orig_bias = count_tokens_ci(original, {positive}) - count_tokens_ci(original, {negative})
        comp_bias = count_tokens_ci(compressed, {positive}) - count_tokens_ci(compressed, {negative})
        if orig_bias != 0 and ((orig_bias > 0) != (comp_bias > 0)):
            errors.append(SemanticError("polarity_flip", pair=(positive, negative), orig=orig_bias, comp=comp_bias))

    # S4: imperative inversion (FMEA V.3 — "do X" → "don't X" / "avoid X" escapes S1)
    IMPERATIVE_POSITIVE = {"do", "use", "run", "call", "include", "set", "enable", "apply", "add"}
    IMPERATIVE_NEGATIVE = {"don't", "avoid", "skip", "exclude", "disable", "never", "remove", "omit"}
    orig_imp_delta = count_tokens_ci(original, IMPERATIVE_POSITIVE) - count_tokens_ci(original, IMPERATIVE_NEGATIVE)
    comp_imp_delta = count_tokens_ci(compressed, IMPERATIVE_POSITIVE) - count_tokens_ci(compressed, IMPERATIVE_NEGATIVE)
    if abs(orig_imp_delta - comp_imp_delta) > 1:
        errors.append(SemanticError("imperative_drift", orig=orig_imp_delta, comp=comp_imp_delta))

    return errors
```

**S3 and S4 are a defense-in-depth layer on top of S1/S2.** FMEA V.2 showed S1's negation count is fooled by simultaneous add-and-drop; FMEA V.3 showed pure antonym swaps (`safe` → `unsafe`) involve zero negation tokens and escape S1 entirely. The polarity lexicon is intentionally small and conservative — false positives trigger a cheap retry; false negatives corrupt meaning silently and are unacceptable.

Full embedding-based semantic similarity is now advanced from §10.3 (Stage 3) to **Stage 2 P1** — ship with S1–S4 first, add embedding cosine once we have production traffic to calibrate the threshold against observed false-positive rate.

#### 3.4.6 Retry policy

```
compress → validate
  if errors:
    retry_with_targeted_fix(errors)  # up to MAX_RETRIES=2
    validate
  if still errors:
    return FALLBACK(original, reason=combined_errors)
```

Targeted fix prompt: "Here is the original. Here is your compressed version. Here are the specific errors you introduced: [list]. Return a corrected version that preserves the original wherever it differs from what you produced — do NOT recompress."

#### 3.4.7 Failure modes

| Mode | Trigger | Handling |
|------|---------|----------|
| Haiku call fails | Rate limit, network, model unavailable | Return `FALLBACK(original, reason="provider_error")`, emit `compression.caveman.fallback=provider_error` tag |
| Structural validation exhausted | 2 retries failed | Return original, tag `compression.caveman.fallback=structural` |
| Semantic validation exhausted | 2 retries failed | Return original, tag `compression.caveman.fallback=semantic` |
| Gate denied | Net-positive gate returned false | Return original, tag `compression.caveman.gate_denied=<reason>` |
| Wenyan requested but `accept_wenyan=False` | Caller misconfigured | Return original, log warning, tag `compression.caveman.gate_denied=wenyan_not_accepted` |
| Pathological expansion | Compressed is larger than original | Return original, tag `compression.caveman.fallback=expansion` |

**Budget assertion (FMEA P.2).** The orchestrator enforces a hard ceiling of 28 tags on any `LLMRequest` before handing off to Pi-Mono, leaving 4 tags of headroom under the 32-key limit. If adding a compression tag would exceed the ceiling, the orchestrator drops lowest-priority compression tags in this order (keep first, drop last):

1. `compression.mode` — **must keep** (A/B switch, load-bearing for all downstream analysis)
2. `compression.pipeline` — **must keep** (which layers ran)
3. `compression.tokens.before` / `compression.tokens.after` — **must keep** (direct-savings aggregate)
4. `compression.bytes.before` / `compression.bytes.after` — **must keep** (direct-savings aggregate)
5. `compression.fallback` — **must keep** (failure attribution)
6. `compression.forge.tokens_saved`, `compression.forge.compactions` — high priority
7. `compression.rtk.bytes_saved_prior` — high priority
8. `compression.caveman.cost_tokens` — high priority (net-positive audit trail)
9. `compression.caveman.intensity`, `compression.caveman.dialect`, `compression.tonl.tokenizer` — lowest priority (reconstructible from harness data)

An `orchestrator.tag_budget_exceeded` event is logged on every drop so the occurrence frequency is visible on the dashboard. If drops exceed 1% of requests sustained, that is a cardinality regression and a PR is cut to reduce the non-compression tag count.

Tag values are strings per Pi-Mono's contract — numeric values are string-encoded and parsed by the A/B harness at aggregation time.

Callers (agents, workflows) interact with the compression layer through a single facade:

### 4.3 Agent transparency

Agents do not know compression is happening. From an agent's point of view:
- Calling `provider.messages.create(...)` produces a response whose body is identical in shape to an uncompressed response.
- Running a tool command via the Stage 4 runtime produces `stdout` that is identical in shape to raw output (just shorter).
- Caveman's output is structurally valid prose in the requested dialect; the agent never sees the original.

The only place the abstraction is visible is the Pi-Mono dashboard, which shows savings as a separate row on the cost breakdown.

### 4.5 Dependency on Pi-Mono non-guarantees

The compression layer **must not** rely on Pi-Mono guarantees that Stage 1 did not make. Specifically:
- Do NOT build tight feedback loops on `tracker.stream_events()` — it polls SQLite every 100ms and event throughput is not guaranteed (alignment-review §6).
- Do NOT depend on Pi-Mono for real-time decision making within a single request. Aggregations are eventually consistent.
- Do NOT read `events.py` coverage-dependent code paths in Stage 2 — Stage 1 QA gap is tracked at 17% coverage on events (alignment-review §3.1).

## 5. QUALITY PRESERVATION STRATEGY

### 5.1 Per-component circuit breakers

| Component | Circuit breaker | Failure mode | Recovery |
|-----------|-----------------|--------------|---------|
| TONL | Round-trip property invariant (`decode(encode(x)) == x`) at shipped-code build time; input validator at run time | Encode fails, decode fails, cycle detected | Raise typed exception; orchestrator falls back to JSON path |
| Forge | `compact` returns original on `no_savings`, `tool_chain_too_long`, or reasoning extraction failure | Rarely triggers in practice | Return original conversation; subsequent requests may re-trigger |
| Caveman | Structural validator + semantic validator + 2-retry targeted-fix loop + net-positive gate | Provider error, validation exhausted, gate denied | Return original prose; tag fallback reason |
| RTK | Subprocess timeout (30s) + binary-missing guard + telemetry-read best-effort | Platform unsupported, binary crash | Disable RTK for session; fall back to unfiltered command output |

### 5.2 Global fail-safe ordering

When any component fails, the orchestrator preserves the following ordering of fallback preference (highest preference first):

1. **Return structurally valid output.** Never return corrupted prose, malformed JSON, broken tool output. If any layer can't guarantee validity, that layer falls back to its input.
2. **Preserve billing accuracy.** Pi-Mono records must reflect actual tokens consumed, NOT intended-compressed-tokens. A fallback event emits the REAL token counts.
3. **Attribute the failure.** Every fallback is tagged with the component name and reason; silent fallbacks are a bug.
4. **Don't cascade.** One component's failure does not disable the others in the same request.

**Enumerated cascade isolation paths (FMEA P.1).** Every row below is an explicit test target in §9.4 chaos tests.

| Failing component | What still must run | What does NOT happen |
|-------------------|---------------------|----------------------|
| TONL encode fails | Forge compaction runs on un-TONL'd history; request still sent (as JSON); Caveman still runs on response; RTK unaffected | Forge is NOT skipped; request is NOT aborted |
| TONL decode fails | Caveman still runs on the raw decoded-as-JSON string; RTK unaffected | Response is NOT returned as error |
| Forge compaction fails | TONL encode ran; request goes to provider with full history (no compaction); Caveman runs on response; RTK unaffected | Request is NOT aborted; history is NOT silently truncated |
| Caveman fails (retries exhausted) | TONL/Forge savings still attributed; request already completed; RTK unaffected; caller receives ORIGINAL uncompressed output | Caller is NOT blocked; savings for other components are NOT discarded |
| RTK fails (binary missing / timeout / crash) | Command output returned raw; subsequent LLM request still runs full compression pipeline; Pi-Mono billing unaffected | Agent workflow is NOT aborted; other tool calls still go through RTK if the binary later recovers |
| Pi-Mono write fails (Stage 1 failure upstream) | Compression components still run (they don't depend on Pi-Mono for execution); savings go untagged for this request | Stage 2 does NOT retry Pi-Mono — that is Stage 1's concern |

**Rule of thumb:** a component's failure is isolated to ITS savings attribution and ITS pipeline slot. No other component sees that failure as input. The orchestrator's `try/except` boundaries are drawn at each component interface, not around the pipeline as a whole.

### 5.3 Validation approach per component

| Component | Validation method | When |
|-----------|------------------|------|
| TONL | Round-trip property tests (Hypothesis), golden file per tokenizer, security-limit tests | CI on every PR |
| Forge | Idempotency property (`compact∘compact = compact`), zero-LLM assertion (mock counts calls = 0), tool-pair safety property, reasoning-preservation property | CI on every PR |
| Caveman | Structural regression fixtures (markdown with embedded code/URLs/paths), semantic negation/number tests, net-positive gate unit tests, full-pipeline integration against Haiku (gated nightly) | CI structural + nightly integration |
| RTK | Subprocess timeout test, binary resolution test per platform, telemetry JSON parse round-trip, concurrent run test | CI + weekly re-vendor verification |

### 6.3 Workload-level vs request-level measurement

Critical design point raised by the Caveman / RTK pay-forward analysis (§0):
- **TONL and Forge** are measurable at the per-request level. Run the same request twice, once with each component enabled, diff input_tokens.
- **Caveman and RTK** only make sense at the workflow level. Run a full workflow (e.g., a BMAD session with 30 agent turns) twice, once with compression on, once off, diff total tokens across all turns.

The harness runs both modes:

```python
async def run_workload(workload: Workload, mode: Literal["request", "workflow"]):
    # Seed pinning (FMEA P.3): both on and off runs consume the same PRNG seed and
    # the same LLM sampling seed. Without this, "savings" is noise, not signal.
    seed = workload.seed
    config_hash = hash_compression_config(workload.config)

    if mode == "request":
        for request in workload.replay_requests():
            on_cost = await track_cost_with_compression_on(request, seed=seed, config_hash=config_hash)
            off_cost = await track_cost_with_compression_off(request, seed=seed, config_hash=config_hash)
            if on_cost.config_hash != off_cost.config_hash:
                raise HarnessConfigDriftError(on_cost.config_hash, off_cost.config_hash)
            yield RequestDiff(on_cost, off_cost)
    elif mode == "workflow":
        on_total = await run_workflow_with_compression_on(workload, seed=seed, config_hash=config_hash)
        off_total = await run_workflow_with_compression_off(workload, seed=seed, config_hash=config_hash)
        if on_total.config_hash != off_total.config_hash:
            raise HarnessConfigDriftError(on_total.config_hash, off_total.config_hash)
        yield WorkflowDiff(on_total, off_total)
```

**Fairness guarantees (FMEA P.3, P.5).**

- Both arms consume the same `workload.seed` for any PRNG-driven behavior — scheduler ordering, random agent selection, synthetic input generation.
- LLM provider calls use `temperature=0` when the workload allows it; otherwise the sampling seed is passed explicitly via the provider SDK's seed parameter (OpenAI `seed`, Anthropic deterministic mode when available). Non-deterministic workloads are explicitly flagged in the report.
- Both arms log `config_hash` at run start; the harness raises `HarnessConfigDriftError` and aborts if the hashes differ. This catches silent drift where one arm runs against a stale config snapshot or a partially-applied config change.
- The `config_hash` also propagates into structured logs (§8.2) and OTel span attributes (§8.1) as `praxis.compression.config_hash`, so any post-hoc dashboard query can filter savings by config generation and exclude runs whose config drifted mid-flight.

## 7. STORAGE & VERSIONING

### 7.1 TONL tokenizer version pinning

Every TONL-encoded payload begins with a header:

```
#tonl v1.0 tokenizer=claude-opus-4-6@2026-04-12
```

Decoder rejects payloads whose tokenizer is not registered in the current tokenizer catalog. The catalog is a Python module `tokenizers/catalog.py` with explicit version pins:

```python
TOKENIZER_CATALOG = {
    "claude-opus-4-6@2026-04-12": AnthropicTokenizer(model="claude-opus-4-6", snapshot_date="2026-04-12"),
    "claude-sonnet-4-6@2026-04-12": AnthropicTokenizer(model="claude-sonnet-4-6", snapshot_date="2026-04-12"),
    "gpt-5@2026-04-12": OpenAITokenizer(model="gpt-5", encoding="o200k_2026"),
    "gemini-3.1-pro@2026-04-12": GoogleTokenizer(model="gemini-3.1-pro", snapshot_date="2026-04-12"),
}
```

When a provider changes their tokenizer, Praxis adds a new entry with a new snapshot date, keeps the old one for historical decode, and sets the new one as default. Round-trip tests catch silent drift.

### 7.2 Caveman dialect rule versioning

Dialects are Python modules; dialect "version" is the Praxis release version. A breaking change to the caveman-English prompt requires a minor Praxis version bump. The Caveman compression tags include dialect version:

```
compression.caveman.dialect=caveman_english@v0.2
```

This lets historical savings reports be replayed against the exact dialect that produced them.

### 7.3 RTK binary version pinning

Vendored binaries carry a version stamp. The wrapper at import time asserts compatibility:

```python
RTK_PINNED_VERSION = "v0.35.0"

def assert_version(binary: Path):
    result = subprocess.run([str(binary), "--version"], capture_output=True, text=True)
    actual = result.stdout.strip()
    if not actual.startswith(RTK_PINNED_VERSION):
        raise RTKVersionMismatchError(f"expected {RTK_PINNED_VERSION}, got {actual}")
```

Upgrades are an intentional, reviewed step with a re-run of the A/B harness to confirm savings numbers haven't drifted.

### 7.4 Migration strategy

When any component's algorithm changes in a way that affects historical decode or savings attribution:
1. Bump the component's version.
2. Add a migration note to `praxis/kernel/compression/CHANGELOG.md`.
3. Re-run the A/B harness nightly; compare deltas across the version boundary.
4. Alert if the savings number drops by more than 5% post-upgrade.

## 9. TESTABILITY NOTES FOR MURAT

This section tells Murat what the architecture has made testable and where the risks live. Murat's test strategy is the authoritative document, but the hooks listed here are the minimum starting surface.

### 9.1 Risk-to-test mapping

| Murat risk (compression series) | Test type | Coverage target |
|---------------------------------|-----------|-----------------|
| **CM1. TONL lossy round-trip** | Hypothesis property + golden fixtures per tokenizer | 100% round-trip on Hypothesis-generated payloads |
| **CM2. Forge breaks reasoning chain** | Targeted fixtures with Anthropic `thinking` blocks pre/post compaction | Every retention-window boundary case |
| **CM3. Forge drops tool_use without tool_result** | Fuzz-test with random tool call / tool result interleaving | 100% pair preservation on synthetic inputs |
| **CM4. Caveman corrupts code in mixed prose** | Golden fixtures: markdown with fenced code, inline code, JSON, YAML, SQL | Structural validator catches all corruption |
| **CM5. Caveman semantic drift (negation, numbers)** | Adversarial prose inputs where negation or numeric meaning is load-bearing | Semantic validator catches flips |
| **CM6. Caveman cost > savings** | Net-positive gate unit tests + harness-measured break-even | Gate blocks below break-even |
| **CM7. RTK binary crash / timeout** | Subprocess timeout test, signal-kill recovery test | Session survives |
| **CM8. RTK telemetry race** | Concurrent invocation stress test, attribution accuracy check | Best-effort with tolerance docs |
| **CM9. Cascade failure across layers** | Chaos test: force each component to fail, assert others still run | 100% isolation |
| **CM10. Tokenizer drift (silent encoder/decoder version mismatch)** | Strict version pinning; decode with old version → rejection test | 100% rejection on unknown version |

### 9.2 Property-based tests (Hypothesis)

**TONL:**
- `P_T1. encode/decode round-trip`: `decode(encode(x)) == x` for Hypothesis-generated nested dicts/lists/primitives.
- `P_T2. Security limit enforcement`: any payload with nesting > 500 raises `TONLSecurityError`.
- `P_T3. Streaming equivalence`: `list(decode_stream(encode_stream(xs))) == xs` for async iterables.

**Forge:**
- `P_F1. Idempotency`: `compact(compact(c)) == compact(c)` for Hypothesis-generated conversations.
- `P_F2. Retention`: the last N messages are always identity-equal to the input's last N.
- `P_F3. Tool pair preservation`: no compaction result has a `tool_use` without its `tool_result` in the same message or the immediate next.
- `P_F4. Zero LLM calls`: mock provider asserts `call_count == 0` across all compaction runs.
- `P_F5. Reasoning preservation, positive case`: if input has reasoning in the compacted range AND the first post-boundary assistant message has no reasoning, the output's first post-boundary assistant message has reasoning copied from the last extracted block.
- `P_F5b. Reasoning non-overwrite (FMEA F.6)`: if input has reasoning in the compacted range AND the first post-boundary assistant message ALREADY has reasoning, the output's first post-boundary assistant message has its ORIGINAL reasoning — the extracted block is discarded, not merged, not appended, not overwritten.
- `P_F6. Reasoning schema drift detection (FMEA F.2)`: fuzz-inject unknown `reasoning_schema_version` values; assert `result.reasoning_preserved == False`, `result.reasoning_drift_detected == True`, and the `forge.reasoning.unknown_schema` alert is emitted exactly once per unknown schema instance.

**Caveman:**
- `P_V1. Structural validator roundtrip`: any compressed text that passes structural validation has identical heading / code / URL / path sets to the original.
- `P_V2. Semantic validator negation`: Hypothesis-generated sentences with negation are flagged when negation count drifts by > 1.
- `P_V3. Semantic validator polarity flip (FMEA V.2)`: for every pair in `POLARITY_PAIRS`, a synthetic sentence that flips the bias from positive to negative (or vice versa) without altering the total negation count MUST be flagged by the S3 check.
- `P_V4. Semantic validator imperative inversion (FMEA V.3)`: a synthetic "do X" → "don't X" / "avoid X" transformation MUST be flagged by the S4 check.
- `P_V5. Gate below floor blocks`: `should_compress(text, tokens < min_tokens)` is always `(False, "below_min_length")`.
- `P_V6. Gate calibration staleness blocks (FMEA V.4)`: `should_compress(..., calibration.age > max_age)` always returns `(False, "calibration_stale")`.
- `P_V7. Gate prediction feedback (FMEA V.5)`: after N synthetic runs where `actual_reads < expected_reads`, the calibration's `break_even_reads` is strictly greater than its initial value.

**RTK:**
- `P_R1. Subprocess budget`: `run_command` with a passthrough no-op command returns within 200ms (binary startup + IPC).
- `P_R2. Binary resolution`: `resolve_binary_path()` returns a file that exists for the test platform.

### 9.4 Integration tests

1. **End-to-end Praxis call through the full compression pipeline** — captures a real Haiku call, runs it with compression on and off, asserts token delta > 0 and validator passed.
2. **Forge trigger in a long BMAD session replay** — replays the Tokonomics Round 4 BMAD session through the compression layer and asserts Forge compaction fires at the expected message count, with tool pairs preserved.
3. **RTK against a real shell environment** — runs `git log`, `docker ps`, `pytest --collect-only` through the RTK wrapper and asserts filtered output matches golden.
4. **Caveman gate decisions** — feeds 20 synthetic prose outputs with varying expected-read counts, asserts gate decisions match the calibrated break-even.
5. **Chaos cascade isolation (FMEA P.1)** — iterates the enumerated cascade table in §5.2. For each row: force the named component to raise `ComponentFailureError`, assert all listed "what still must run" components DID run (verified by span presence), assert the listed "what does NOT happen" outcomes did NOT happen (verified by negative assertions on request completion and downstream effects). Test must cover all 6 enumerated rows.
6. **Pi-Mono reconciliation round-trip (FMEA P.4)** — produce 100 compression-tagged requests through a real tracker; run `tracker.get_cost_summary(Filter(tag_match={"compression.mode": "on"}))`; parse the compression tag aggregates and sum `(tokens.before - tokens.after)` across all records; assert this sum equals the A/B harness's reported savings within **0.5% drift** (Matrix 5). Drift > 0.5% fails the test — it indicates either a tag encoding bug or an aggregation bug, since Stage 1's Decimal math pins `QUANTUM = 1e-10` (eight orders of magnitude below this threshold), so any visible drift is non-rounding.
7. **RTK orphan bucket attribution (FMEA R.8)** — issue `rtk.run_command` calls with no downstream `LLMRequest` within the 60s window; assert the savings land in the orphan bucket with the `compression.rtk.orphan=true` tag and appear in the dashboard's orphan-rate metric.
8. **A/B harness config drift (FMEA P.5)** — run the harness with deliberately mismatched config hashes between on and off arms; assert `HarnessConfigDriftError` is raised and the run is aborted before any savings are recorded.
9. **Gate calibration staleness (FMEA V.4)** — write a synthetic `CalibrationSnapshot` with `refreshed_at` older than `max_calibration_age_seconds`; invoke Caveman; assert the gate denies with `reason=calibration_stale` and no Haiku call is made (mock provider's `call_count == 0`).
10. **Gate prediction feedback loop (FMEA V.5)** — simulate 30 compression runs where the actual downstream reads are half the predicted value; run the nightly calibration step; assert `break_even_reads` increased by at least 1 and `caveman.calibration.adjusted` event was emitted.
11. **Tag budget overflow (FMEA P.2)** — construct a synthetic `LLMRequest` with 20 non-compression tags, run the full pipeline, assert only the 5 must-keep compression tags land on Pi-Mono, assert `orchestrator.tag_budget_exceeded` event was emitted with the dropped tag list.

## 10. OPEN QUESTIONS

These need stakeholder input or data before commitment. Amelia should not block on them for Stage 2 P0; defaults are listed.

### 10.1 Is Caveman in Stage 2 P0 at all?

**Question:** Caveman's LLM-driven design means compression costs tokens. The net-positive gate keeps it honest in aggregate but introduces complexity. Is Caveman still in scope for Stage 2 P0, or should it slip to Stage 3 with a rule-based placeholder?

**Default:** Include in Stage 2 P0 with the gate and mandatory A/B harness reporting. If the break-even N calibration comes out above 5 (too demanding), re-scope.

**Who decides:** Andrey, via the 2.1.5 elicitation step. **This is the top elicitation target.**

### 10.2 What's the acceptable Caveman fallback rate?

**Question:** Structural and semantic validators will fail sometimes. What fallback percentage is acceptable before the whole component is considered a failure?

**Default (post-matrix, Matrix 1):** **3% combined fallback rate** (structural + semantic) over any 24-hour window triggers a warning alert. **7% disables Caveman** for the workload until investigated. Thresholds may loosen to 5% / 10% after the first 30 days of production if observed fallback rate is stable and no silent degradation is detected.

Rationale: the matrix prefers 3% / 7% over the prior 5% / 10% default by a 0.05 margin on weighted score. The deciding factor is Praxis's pre-launch pitch — *"measured savings with quality preservation"* — which makes the "user sees silently degraded output" failure mode the most expensive thing in the whole architecture. Starting tighter and loosening on evidence is the conservative play.

**Who decides:** Murat based on production tolerance; Andrey based on product tolerance. Matrix 1 results are captured in `requirements-validation.md`.

### 10.3 Semantic similarity via embeddings

**Question:** Current semantic validator is regex-based (negation + numbers only). Full similarity via embedding cosine distance would catch meaning-preserving drift. Is the extra latency and cost justified?

**Default:** Not in Stage 2 P0. Add in Stage 3 when Mem0 is already wired and embeddings are cheap.

**Who decides:** Winston + Murat.

### 10.4 RTK concurrency safety and orphan attribution

**Question:** RTK's telemetry DB is global. Multiple concurrent `run_command` calls from a parallel Praxis workflow may produce interleaved rows. How accurate must per-request savings attribution be? And what happens when an RTK call produces savings but no downstream `LLMRequest` consumes them (the orphan case, FMEA R.8)?

**Defaults (post-FMEA):**
- **Concurrency attribution:** best-effort — attribute the most recent N rows to the N most recent invocations in timestamp order, documented tolerance ±2% on savings total. Exact attribution requires an RTK fork (not in scope).
- **Orphan timeout:** 60 seconds. If no downstream `LLMRequest` arrives in that window, the savings are bucketed as orphan with `compression.rtk.orphan=true` on the nightly rollup.
- **Orphan rate alert threshold:** sustained > 5% over 24 hours is an investigation trigger (Matrix 4, Elicitation Round 1). A high orphan rate implies agent workflows are producing CLI output no LLM ever reads, which is a workflow-efficiency problem rather than a compression problem.

**Who decides:** Andrey. Flag if the A/B harness shows attribution drift > 5% OR orphan rate > 5% sustained.

### 10.5 Forge trigger defaults per provider

**Question:** The default token_threshold is 70% of "the context window" — but context windows vary per model (Opus 4.6 is 1M, GPT-5 is 400K, etc.). How does Forge pick the threshold?

**Default:** Per-provider, per-model defaults in a config table. Praxis ships defaults for Anthropic Opus 4.6, Sonnet 4.6, Haiku 4.5, OpenAI GPT-5, Google Gemini 3.1. Caller can override.

**Who decides:** Winston. This is a config, not a design open question.

### 10.6 Wenyan (文言文) dialect rollout

**Question:** Wenyan compression is powerful (80–90% reduction) but only valid when downstream consumers correctly tokenize classical Chinese. Is any near-term Praxis workflow known to need it?

**Default:** Ship behind a hard gate (`accept_wenyan=False` default). No Stage 2 use case currently needs it. Revisit when a multilingual workload lands.

**Who decides:** Andrey.

### 10.7 Tokenizer catalog update cadence

**Question:** Providers change tokenizers silently (model snapshots, new encoding versions). How often does Praxis refresh the catalog?

**Default:** Monthly manual refresh, matching Stage 1's pricing snapshot cadence (§10.5 of pi-mono arch). Automated drift detection as a Stage 3 follow-up.

**Who decides:** Andrey.

### 10.8 Tool-call payload safe zone heuristics

**Question:** Caveman's boundary detector must recognize JSON, YAML, SQL, XML fenced regions inside prose. What's the detection rule — regex, parser-based, content-type hints from the caller?

**Default:** Regex-based with caller hints. Caller may pass `safe_regions: list[Span]` to explicitly mark boundaries. Regex fallback detects markdown code fences plus inline code plus common tool-call prefixes (`{`, `---`, `SELECT`, `<`).

**Who decides:** Winston after first integration test suite.

### 10.9 What if a caller wants uncompressed output for debugging?

**Question:** Developers debugging may want to see what the LLM actually produced before Caveman. Provide a pass-through mode?

**Default:** A `compression.bypass=true` tag on the `LLMRequest` forces the orchestrator to skip compression entirely. Compressed and uncompressed paths both emit the same shape of tags for consistency.

**Who decides:** Winston. Confirmed.

### 10.10 A/B harness scheduling and storage

**Question:** How often does the harness run, and where does its data live?

**Default:** Nightly via cron, SQLite-backed history at `_bmad-output/test-artifacts/praxis/compression/harness.db`. Reports regenerate into the planning-artifacts tree for committed review. Stage 7 dashboard queries the same DB.

**Who decides:** Winston.

### 10.11 Caveman structural bullet-drift threshold calibration

**Question:** The H5 check in §3.4.4 flags bullet-count drift above a configurable threshold (default 0.15). This is a placeholder. What's the right threshold, and how do we calibrate it without training a model?

**Default:** Keep `bullet_drift_threshold = 0.15` until the A/B harness produces a labeled corpus (≥ 200 compression outputs) with ground-truth labels "true compression merge" vs "false corruption merge". Set the threshold at the 95th percentile of the true-merge ratio distribution. Re-run calibration quarterly or whenever a Caveman dialect's prompt template changes.

Until calibrated, bullet-drift false positives will trigger needless retries — acceptable cost, non-blocking for Stage 2 P0.

**Who decides:** Winston + Murat. Flagged by FMEA V.10.
